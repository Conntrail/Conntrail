How it works

Four steps, then one classifier. Nothing here is inferred beyond what was measured.

  1. Your node runs normally — output is unchanged.
  2. A cheap model (never your agent's model) generates three perturbed variants of the input: similar, neutral, opposite.
  3. Conntrail re-runs the node on all four inputs and computes normalized Shannon entropy over the routing outcomes: 0.0 = never flips, 1.0 = maximally unstable.
  4. A fixed priority table names which dimension flipped the route first (opposite > neutral > similar) and the counterfactual route — "remove that dimension and the agent takes the other path."

It also classifies failures

From signals the SDK already produces, not invented categories:

  • exception — the node raised
  • retry_loop — rate-limit retries exhausted
  • timeout — exceeded the time budget
  • malformed_output — no route signal found
  • none — a clean, resolved success

Stability labels

confident

Entropy below 0.25. The route holds under every perturbation.

boundary

Entropy 0.25–0.60. One dimension can move the decision.

fragile

Entropy above 0.60. The route is a coin-flip on phrasing.

Conntrail shows measurements. It recommends nothing and claims no savings — every figure is derived from a signal it captured. Findings recommend; the human decides.
