The method

How it works

Four steps, then one classifier. Nothing here is inferred beyond what was measured.

  1. Your node runs normally. Output, latency and cost are unchanged; Conntrail observes the routing decision, it never rewrites it.

  2. A cheap model, never your agent's model, generates three perturbed variants of the input: similar, neutral and opposite.

  3. Conntrail re-runs the node on all four inputs and computes normalized Shannon entropy over the routing outcomes: 0.0 means the route never flips, 1.0 means maximally unstable.

  4. A fixed priority table names which dimension flipped the route first (opposite, then neutral, then similar) together with the counterfactual route: remove that dimension and the agent takes the other path.

It also classifies failures

From signals the SDK already produces, not invented categories:

  • exceptionthe node raised
  • retry_loopretries exhausted
  • timeouttime budget exceeded
  • malformed_outputno route signal found
  • noneclean, resolved success
